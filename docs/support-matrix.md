## Current runtime requirements

- Node.js `^22.12.0 || ^24.0.0 || >=26.0.0`, matching the pinned Vitest 5 runtime range. Node 22.14 includes `--experimental-strip-types`; this supports lowering the original project-specific 22.23.1 gate. Node 23/25 are excluded because Vitest's declared engine range excludes those lines.
- Docker Engine/daemon and Compose v2.24.4 or newer.
- Verified packaged image mode requires Node/npm and Docker Engine/daemon with Compose; first run also requires registry access for pinned images. The tested wallet image is linux/amd64.
- Maintainer source mode still needs Git, curl, OpenSSL, tar, Rust stable and Cargo for a source build of the pinned wallet.
- First packaged run needs registry access to retrieve pinned images. Previous source checkout needed GitHub, crates.io and pinned image registries.
- Fedora Linux 44 x86_64 is reproducibly verified end to end using both the external npm tarball and public npm registry package. The project owner reports later successful Ubuntu and macOS tests, but the exact environments, commands, and outcomes have not been retained; these are not yet independently reproducible or verified here. ARM64, Windows/WSL, and CI runners remain unverified.

## Reproducibility details still needed for Ubuntu and macOS

To promote either owner report to reproducible host evidence, retain a sanitized report or log with the exact OS release and CPU architecture; Node/npm and Docker/Compose versions; public registry versus tarball installation source; whether image cache was cold or warm; each command run and its result (`doctor`, `up`, `test`, `down`, and library import if tested); any failure output; and elapsed times if measured. Do not include usernames, home paths, wallet identities, addresses, or secrets. The historic failures above remain in the record but are not the only current status: the newer success reports are explicitly captured separately.

The Node floor is based on the locked Vitest 5.0.3 package engine (`^22.12.0 || ^24.0.0 || >=26.0.0`) plus Nivyr's use of `--experimental-strip-types`, introduced in Node 22.6 according to the [Node.js v22.14 TypeScript docs](https://nodejs.org/download/release/v22.14.0/docs/api/typescript.html). Node 22.14 is therefore inside the declared dependency/runtime range. The later macOS success report lacks the Node version and logs, so it does not establish an additional reproducible runtime result.

The Cargo policy follows the [Cargo configuration reference](https://doc.rust-lang.org/cargo/reference/config.html): `http.timeout` defaults to 30 seconds and can be overridden with `CARGO_HTTP_TIMEOUT`; registry retry count is configurable through `CARGO_NET_RETRY`. The failure reported by PC #2 was a 30-second no-data timeout for a sparse-index crate path. Nivyr now supplies bounded `120` and `6` defaults, while preserving explicit caller overrides.
