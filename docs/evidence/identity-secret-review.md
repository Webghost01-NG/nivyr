# `identity_secret` Evidence Review

Classification: **confirmed non-sensitive placeholder**.

The field in `bootstrap/wallet-created.json` did not contain an upstream wallet identity. Its value was an omission marker, and the file was committed as static bootstrap evidence in Nivyr commit `6826835f9e7ca9186db40513e3458ccbf2ff4d24`. No Nivyr source or evidence writer emits that field. The current copy now labels the field as redacted/not captured to prevent confusion.

The pinned upstream wallet tool does create sensitive material. At `zcash-devtool` commit `5a26ee854e634a4e88d1d79dab13f8fbb1eac6b8`, `src/commands/wallet/init.rs` documents `--identity` as an age identity used to encrypt the mnemonic. Its wallet initialization path generates an age X25519 identity, writes its secret form to the identity file, and passes its public recipient into wallet initialization. `src/config.rs` functions `init_with_mnemonic`, `encrypt_mnemonic`, `decrypt_mnemonic`, and `get_wallet_seed` show that the wallet mnemonic is encrypted to that recipient and later decrypted with the identity. The actual age identity therefore must remain private; it is not the placeholder stored in this evidence file.

Repository source-mode history stored wallet identity and data under ignored `.cache/runtime`. The npm package now stores runtime state in the consumer project's `.nivyr/` directory, which is ignored as a whole; bootstrap code writes wallet directories with restrictive permissions. The published evidence contains no age identity, mnemonic, private key, or wallet database. The evidence pipeline recursively redacts identity/secret-like fields, age identity strings, and home/temp local paths before integration observations are written.

The field first appears in the public branch history with the bootstrap evidence commit above and remains in later snapshots as the same non-secret omission marker. No history rewrite is warranted for this field. A broad scan of an intermediate sanitizer-test commit matched its short, deliberately synthetic age-key-shaped fixture; it is not a valid key, and the current test constructs that marker at runtime to avoid scanner noise. No valid age identity, private-key PEM, GitHub token, AWS key, or bearer credential was found in reachable Git objects or the current tree. `gitleaks` was not installed, so this review used local Git/object inspection and format-specific scans instead.

The associated bootstrap was disposable local regtest. Because the recorded field is not key material, no wallet rotation or invalidation is required. No mainnet/testnet wallet or external service credential is involved.
